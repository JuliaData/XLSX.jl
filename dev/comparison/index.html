Compared with Python's readers

This page sets XLSX.jl's features beside those of three Python packages often used to read Excel files: python-calamine (Python bindings for the Rust calamine reader), fastexcel (built on calamine and Apache Arrow) and openpyxl. It is meant to help you choose, or to help you move from one to another.

The Python columns were checked on 2026-11-14 against each project's documentation and type stubs, for python-calamine 0.9.1, fastexcel 0.21.0 and openpyxl 3.1. "Not documented" means the project's documentation and public API don't mention the feature. It may still exist in a form they don't describe. In short:

  • python-calamine and fastexcel only read. They read more file formats than XLSX.jl, but they can't write files or read formatting, formulas or objects. On tables, XLSX.jl's readtable is faster than python-calamine and about as fast as fastexcel (see Speed).
  • openpyxl reads and writes .xlsx files, as XLSX.jl does, with a similar range of features, but it is much slower to read and to write.
  • XLSX.jl reads and writes .xlsx files, edits them in place, and covers formatting, charts and Excel's newer features. It reads only the Office Open XML formats.

Speed

All the times below were measured on 2026-11-15 on the same machine (Windows, 8 threads; Python 3.13). XLSX.jl's are those of the code for the next release. The method is in bench/README.md.

Reading

On the benchmark fixtures, XLSX.jl's XLSX.readtable reads a table 10 to 17 times as fast as openpyxl, in 0.4 to 0.8 times python-calamine's time, and in about the same time as fastexcel (0.8 to 1.5 times its time). The exception is the smallest table (100 rows), where fixed costs dominate and python-calamine and fastexcel are about 3 times as fast. Times in milliseconds (medians), for a few of the fixtures:

Writing

python-calamine and fastexcel can't write, so here openpyxl is set beside the two writers most used in Python: XlsxWriter, which pandas and Polars use to write Excel files, and rustpy-xlsxwriter, Python bindings for the Rust rust_xlsxwriter. Each writes the same table, values only, read beforehand and not timed. XLSX.writetable writes it 7 to 24 times as fast as openpyxl and 4 to 10 times as fast as XlsxWriter (the lower figures are against their faster modes), and in 0.85 to 1.4 times rustpy-xlsxwriter's time. With streaming=true it takes 0.6 to 1.0 times rustpy-xlsxwriter's time. Times in milliseconds (medians):

XLSX.jl writes from the table readtable returns; the Python writers write from a list of rows (a list of dictionaries for rustpy-xlsxwriter), one row at a time where the writer takes rows. On the smallest table (100 rows) XLSX.jl takes 3 ms, XlsxWriter 15 ms and rustpy-xlsxwriter 4 ms.

Opening a workbook with XLSX.openxlsx to read or edit it does more work than readtable or writetable, and isn't compared here.
